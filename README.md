## 📚 Tópicos e Conceitos Abordados

Baseado na trilha de aprendizado da DataCamp, este repositório cobre os seguintes pilares de versionamento de código:

### 1. Fundamentos do Git
* O que é controle de versão e por que usá-lo.
* Inicialização de um repositório (`git init`).
* Verificação do estado do projeto (`git status`).
* O ciclo de vida dos arquivos: *Working Directory*, *Staging Area* (`git add`) e *Repository* (`git commit`).
* Histórico e logs de alterações (`git log`).

### 2. Navegação no Tempo e Desfazendo Alterações
* Visualizando diferenças entre commits (`git diff`).
* Retornando a versões anteriores e descartando alterações não commitadas.
* Utilização do comando `git checkout` / `git restore` para gerenciar o estado dos arquivos.

### 3. Trabalho com Branches e Colaboração
* Criação e alternância entre branches (`git branch`, `git checkout -b`).
* Boas práticas de ramificação para desenvolvimento de novas funcionalidades.
* Processo de mesclagem (`git merge`) e estratégias para resolução de **conflitos de merge**.
* Integração com repositórios remotos no GitHub (`git clone`, `git push`, `git pull`, `git fetch`).

## 🛠️ Comandos Essenciais (Cheat Sheet)

Aqui estão alguns dos principais comandos praticados durante os estudos:

| Ação | Comando | Descrição |
| :--- | :--- | :--- |
| **Inicializar** | `git init` | Cria um novo repositório Git localmente. |
| **Adicionar** | `git add <arquivo>` | Move arquivos do diretório de trabalho para a *staging area*. |
| **Commitar** | `git commit -m "mensagem"` | Salva as alterações da *staging area* no histórico. |
| **Status** | `git status` | Exibe o estado atual dos arquivos (modificados, staged, etc.). |
| **Histórico** | `git log --oneline` | Mostra o histórico de commits de forma resumida. |
| **Branches** | `git checkout -b <nome>` | Cria e muda para uma nova branch. |
| **Enviar** | `git push origin <branch>` | Envia os commits locais para o repositório remoto. |
| **Atualizar** | `git pull` | Baixa e mescla as alterações do repositório remoto. |
